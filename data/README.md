# Data specification

`demo.csv` is generated by `python demo_data.py` with a fixed seed. The synthetic nearby (C1) and next contract (C2) series share a price factor with the spot series. Each has its own noise, with seven explicitly set stress intervals.

## CSV for a market-data run

| Column | Unit | Meaning |
|---|---|---|
| `month` | `YYYY-MM` | Label for the end of the interval. Supply consecutive months in ascending order. |
| `spot_myr_t` | MYR/metric tonne | Spot price at the observation endpoint. It must be positive and finite. |
| `futures_change_c1` | MYR/metric tonne | Signed P&L on the one-tonne long futures leg during the interval. Leave blank on the first row only. |
| `futures_change_c2` | MYR/metric tonne | Optional next-contract series with the same conventions. |

```csv
month,spot_myr_t,futures_change_c1,futures_change_c2
2017-10,2631.00,,
2017-11,2543.00,-67.00,-70.00
2017-12,2456.00,-92.00,-86.00
```

These rows are illustrative. The dashboard uses a common evaluation period for all windows. Supply at least 36 monthly changes before evaluation starts and at least two during evaluation.

## Building data from distinct futures contracts

1. Choose one observation rule and preserve both source dates. For a first-trading-day study, use the first date on which both sources have an eligible quote. Align intervals by the actual start and end dates. Check publication times and document which prices were observable when entering the hedge.
2. Choose the eligible contract at each interval start using information available then. Decide when it must roll. Keep the contract codes, settlement prices and roll calendar.
3. For an interval with a roll, sum the same-contract price changes across the legs actually held. Avoid treating the price gap between the outgoing and incoming contracts as realized P&L.
4. Record the provider, data vintage, frequency, units, settlement convention, missing observations, filters and redistribution terms. A monthly-average spot quote calls for an exposure and hedge definition consistent with that averaging window.

The CLI validates the prepared CSV and applies the hedges. It assumes the signed futures changes reflect the relevant instruments and timing. Keep restricted input and output paths out of version control.
